# Claims audit

Audited Mon Oct 12 2026 against commit 6692db1. Every factual claim on the public surfaces (README.md, the rendered page `site/`, plus the linked READMEs) checked against the repository's own raw data.

**Verdicts: 124 claims: SUPPORTED 83, OVERSTATED 24, UNSUPPORTED 0, CONTRADICTED 11, STALE 6**

How each check was made:

- **Page text**: `claims-audit/render.py` serves `site/` on 127.0.0.1:8777, drives headless Chromium (`--mute-audio`), opens every `<details>`, and saves the visible text plus Figure 2 (the per-loop drawer) for the reverse loop, the forward add and the forward sum on every CPU model the switcher offers, in both columns. The output is `claims-audit/page-text.txt`. The server stops when the script ends. No console errors.
- **Numbers**: `claims-audit/recompute.py` recomputes each numeric claim from the raw files (`results/`, `dayone/results/`, `audit/out-recompute.txt`) and writes `claims-audit/recompute-out.txt`. The tags in the Recomputation column ([P2], [C1] and so on) point to its lines.
- **Links and downloads**: `claims-audit/links.py` HEAD-checks every external link on the page and in the README, plus every pinned download in `corpus/projects*.json` and `programs/*/fetch.sh`. Its output is `claims-audit/links.txt`.
- **Google's post**: fetched live with curl (HTTP 200, 147,442 bytes) and read as text (see "Google quote").
- **`python scripts/check.py`**: run once during this audit. Exit 0, "ALL CHECKS PASSED", including the site checks.

Verdicts used: SUPPORTED, OVERSTATED (the data shows something weaker or narrower), UNSUPPORTED (no data in the repo backs it), CONTRADICTED (the repo's own data or page says otherwise), STALE (true of an earlier state, not of the current data or page).

## Google quote (live check)

`https://security.googleblog.com/2024/11/retrofitting-spatial-safety-to-hundreds.html` answered 200 on Oct 12 2026.

- **Title, date and authors.** The title is "Retrofitting spatial safety to hundreds of millions of lines of C++", dated November 15, 2024, posted by Alex Rebert and Max Shavrick (Security Foundations) and Kinuko Yasuda (Core Developer).
- **The sentence is exact.** The post says: "Hardening libc++ resulted in an average 0.30% performance impact across our services (yes, only a third of a percent)." So 0.30% is an average over "our services": a fleet-wide figure, not a per-loop one.
- **Context the project does not quote.** The same paragraph says that "a handful of performance-critical code paths still require targeted use of explicitly unsafe accesses". It also says that profile-guided optimization "further improved performance", and that a fixed check took the overhead "from 0.35% to 0.3%".
- **Earlier rollout figures unchecked.** Figures for an earlier rollout (about 0.9% QPS, about 2.5% latency) were seen only in a search summary; they cannot be checked against this page, which contains neither "QPS" nor "latency".

## External links and pinned downloads (claims-audit/links.txt)

- **Repository links answer 404.** `github.com/JacoboPacheco/third-of-a-percent`, its Actions run pages and `actions/workflows/measure.yml` all answered 404 to a logged-out client at the time of the audit.
- **The page's other links work.** The Google post and the Google Fonts stylesheet answer 200. The bare `https://fonts.googleapis.com` answers 404, but it is only a `preconnect` origin, not a link.
- **Every pinned download is still there (59 URLs).** That covers 44 census projects and their extra archives, plus the json and fmt inputs. Each answers 200: the GitHub archives redirect to codeload.github.com, the two Eigen archives are served from gitlab.com, and the release assets come from release-assets.githubusercontent.com. Where the server reports a size and the repo records one (`json.hpp` and the two simdjson single headers), the sizes match. HEAD requests cannot check sha256; the runs' own `sha256sum -c` did that when the files were fetched.
