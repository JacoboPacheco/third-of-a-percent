## A correction made on the way (check this first)
The pooled file counted every job twice: each job's results file exists in two download copies under `results/realworld-<id>/` (one under `realworld-run-<id>/jobs/`, one beside it), and `realworld/pool_rw.py` read both. Job counts read 24 (really 12), EPYC 7763 20 (really 10), EPYC 9V74 4 (really 2), and intervals were too narrow (about 0.7 times the true width). Fixed in `realworld/pool_rw.py` (`_unique_content`: one path per distinct sha256), pooled file regenerated, README tables regenerated, `python realworld/check.py` passes. Point ratios are unchanged (geometric mean of per-job values). Consequence: EPYC 9V74 has 2 jobs, below the 3 a reading needs, so it has no reading; only AMD EPYC 7763 does.
